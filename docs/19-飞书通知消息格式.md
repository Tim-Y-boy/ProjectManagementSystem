# 19 · 飞书消息格式与定位契约

核对日期：2026-10-27。依据 notify-card、review-card、daily-report-card、project-brief-card、weekly-progress-card 及 project-delay-digest。消息字段由代码生成，本页不提供容易过时的整份硬编码 JSON。

## 1. 构造器与样式

| 构造入口 | 场景 |
|---|---|
| buildNotifyCard | 任务、计划变更、个人汇总及工作日报等；标题、字段、分组、正文和链接按钮 |
| projectBriefCard | 项目群简报，schema 2.0；进度表、图片、关注项、可点击项目及负责人提及 |
| weekly-progress-card / weekly-progress-notice | 按周、项目和真实任务祖先结构展示缺填项 |
| buildProjectDelayDigest | HR 延期日报，红色标题，按项目分组，每 12 项分片 |
| closures / supplement-notice-card | 结项审核、报告待阅、补填知晓及更正 |

通知内容应区分项目标题、任务标题、人员、截止、状态和操作。业务文本需要转义，不能直接插入可执行 HTML 或构造任意 @ 提及。纯文本 fallback 保留关键结论和入口，不保证与卡片布局完全相同。

## 2. 审批深链

| 事项 | 当前网页目标 |
|---|---|
| 任务验收待处理 | /approvals?taskId=… |
| 新任务确认 | /approvals?confirmId=… |
| 任务某轮审批结果 | /approvals?taskId=… 或 confirmId=…，附 at；历史列表使用 taskLogId |
| 计划变更待审／结果 | /approvals?changeId=… |
| 结项申请审核／详情 | request 定位具体申请，审批入口 /approvals |
| HR 报告待阅 | 具体结项报告及 notice，当前报告兼容路由转入 /closures |
| 合理补填知晓 | /my-todo?tab=inform&notice=… |
| 周进展补填 | 任务定位加 weekStart，区分单任务链接与汇总入口 |
| 已完成任务退回执行 | /tasks?projectId=…&taskId=… |

处理权限仍由服务端检查。登录回跳和小屏映射必须保留定位参数，不能把具体事项链接降级成无参数的列表页。旧 /plan-changes 是兼容重定向，新增通知不再使用它作为无定位目标。

## 3. 审核卡片回写

发送时在 notifications.response 保存 reviewCard、reviewRef 与 message_id。审批结果变化后异步修改原消息：已审核、已退回、已撤回，或预审通过后已转终审。任务按原通知对应的首次结果匹配，不用任务此刻的状态覆盖以前的审批轮次。

每分钟扫描近 14 天记录，失败独立重试，不回滚已经完成的业务审批。缺少 message_id、关联不明确或平台不支持更新的旧消息不能保证回写；已经完成同步的历史卡片不会自动全量重写。

## 4. 汇总与日报

- 个人待办：按当前执行、确认、验收、变更等分类组织，任务仍保留具体入口。送达不等于处理完成。
- 工作日报：daily_work_report，展示上一个工作日创建的进展，最多展示 30 条，正文摘要最多 76 个字符；早于提交日期的 workDate 标注补填。入口 /daily-report，完整列表由系统页面提供。
- 项目群简报：project_brief_group，进度图依赖中文字体；关注项由结构化结果或可选模型生成，AI 内容标注初步研判。图片、卡片及纯文本降级以服务返回结果判断。
- 周进展：weekly_progress_missing，祖先行只用于层级，不计入缺填数；个人／群接收人和所属周独立记录，补填链接保留 weekStart。
- HR 延期日报：hr_project_delay_daily_N，查询未完成、未取消末级任务，按当前截止计算自然日延期；没有延期也发送零项摘要。日报不删除或改写延期事实台账。

## 5. 核对方式

核对 notifications 的 type、target、success、response、sent_at 和对应业务记录。已读／知晓状态、业务审批状态、平台送达是三种独立事实。卡片按钮只是打开系统，不能宣称点击即批准或确认知晓。

调度、收件人、禁发开关和补偿策略统一见 [06 通知](06-飞书对接.md)。使用合成数据及本环境测试收件人核验，不在文档内保存真实群 ID、人员 ID、消息 ID 或凭据。
