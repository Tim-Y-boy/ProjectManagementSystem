# 数据库结构

使用 PostgreSQL 与 TypeORM；迁移在 server/src/migrations，实体在 server/src/entities。不要使用 synchronize 替代迁移，也不要把生产数据作为示例数据。

| 数据域 | 主要表或结构 |
|---|---|
| 身份与组织 | users、user_roles、departments |
| 项目与任务 | projects、project_owners、tasks、task_assignees、task_logs |
| 过程资料 | task_daily_updates、task_assets 及资料关联 |
| 计划变更 | plan_changes、plan_change_items |
| 结项与通知 | project_closures、closure_notices、notifications |
| 周报 | project_weekly_reports、project_weekly_report_settings、project_weekly_report_amendments、project_weekly_report_versions |
| 周报投递 | project_weekly_notification_deliveries |

周报以 project_id、week_start 联合唯一，week_start 是周一；状态为 missing/draft/submitted。正式 version 和修改稿 draft_version 分开检查。修改稿使用 proposed_content，审批前不改变正式正文。每份周报至多一份草稿和一条待审批修改申请。

projects.weekly_report_owner_id 指定填报人；submitted_by 保留正式提交人。工作日报已读由服务端保存，周报更新已读保存在当前浏览器。

备份不包含数据库行、转储或运行时附件。全部迁移只应在自行配置的数据库上运行。

## 资料版本

task_assets.current_version_id 指向当前版本，task_asset_versions 保留资料 ID、版本号、文件路径、上传人、时间及可选说明。迁移为已有文件分别生成 v1，不根据同名自动合并。版本写入、当前版本切换及日志在事务内完成；关联和版本更新通过项目锁协调。

结项快照保存版本标识及文件字段，历史报告按冻结路径下载。文件缺失时保留版本记录，接口返回可用性标识。人工历史归并必须先备份并保留版本及来源映射审计。
