# 11 · 飞书接入、组织同步与移动登录

核对日期：2026-10-27。依据 auth、feishu、bot 模块和前端 Login.vue、feishu-sso.ts；控制台配置须在自己的应用中核对。

## 1. 三条链路

| 链路 | 作用 | 网络条件 |
|---|---|---|
| 网页登录与移动 H5 | 登录后查看、填写、审批、报告 | 用户设备能够访问 WEB_FRONT_URL 和回调地址 |
| 服务端主动通知 | 待办、审批、日报及结项消息 | 服务端可以访问飞书 API |
| 机器人长连接 | 用户提问后查询业务 | 服务端向飞书建立出站连接；不要求事件 HTTP 公网回调 |

机器人可以回复不代表手机可以打开系统网页。内网部署需要相应网络通路，手机不能用电脑 localhost。

## 2. 自建应用与配置

在自己的飞书开发者后台创建企业自建应用，配置网页主页、OAuth 回调、通讯录范围及消息权限。使用机器人时启用机器人能力、消息接收事件 im.message.receive_v1 和长连接模式。配置变更按平台要求发布后生效。

系统使用 FEISHU_APP_ID、FEISHU_APP_SECRET、FEISHU_REDIRECT_URI 和 WEB_FRONT_URL。开发示例分别为 http://localhost:8081/api/auth/feishu/callback 与 http://localhost:5173；Docker 同源入口可使用 http://localhost:8088/api/auth/feishu/callback。正式部署换成自己设备可访问的地址。

通讯录读权限和授权范围必须覆盖需要同步的部门及员工；消息发送要求目标用户在应用可用范围，群消息要求机器人在群内。飞书文件搜索使用 GET /api/feishu/docs/search?q=，没有应用配置或权限不足时页面允许改用普通链接；保存链接不赋予文件访问权限。

## 3. 登录行为与接口

| 入口 | 当前行为 |
|---|---|
| 普通电脑／手机浏览器 | 网页 OAuth，授权页显示方式由客户端决定 |
| 飞书桌面端 | 网页 OAuth，不使用桌面 H5 JSSDK 免登 |
| 飞书手机端 | 先尝试 requestAccess / requestAuthCode，失败回退网页 OAuth |
| OAuth 回调 | 后端用 code 换飞书身份，再签发系统 token 并重定向前端 |

GET /api/auth/feishu/authorize 返回授权入口及配置状态；POST /api/auth/feishu/login 接收网页 code；POST /api/auth/feishu/free-login 接收端内 code。两类 code 交换方式不同。登录页保存 redirect，成功后返回原目标，仍受业务权限校验。

Mock 是调试通道。是否显示入口还受密码配置影响，因此生产必须同时设置 FEISHU_MOCK_LOGIN=false 并清空 FEISHU_MOCK_PASSWORD。公开版没有内置 Mock 密码；自行设置密码后才能使用演示账号。

## 4. 组织和权限同步

POST /api/feishu/sync 仅 admin，异步触发全量同步并返回 triggered，不表示同步已经成功。02:00 定时同步没有显式设置时区，按进程环境运行。同步结果写 feishu_sync_logs，登录可触发单用户兜底同步。

部门保存飞书 ID、父 ID 和负责人身份；用户保存飞书身份、主部门和启用状态。负责人字段优先 leader_user_id，再读 leaders 中 leaderType=1 的 leaderID；同步时请求 user_id 类型并回填 departments.head_user_id。当前一个部门使用一个主负责人，同一人可负责多个部门。

有效 dept_head 与 managedDeptIds 从负责人关系计算；手工角色保存在 user_roles。组织同步、角色分配、账号停用与已签发登录态是不同问题，权限调整后需要获取新的身份。FEISHU_ADMIN_USER_IDS 可配置本环境初始管理员，不把真实人员 ID 写进源码。

## 5. 机器人与手机路由

FEISHU_BOT_ENABLED 控制长连接；同一应用不要让非预期的开发、生产实例竞争事件。事件由 bot-channel.service.ts 接收，关键词由 bot-intent.ts 解析，查询由 bot-query.service.ts 执行；可选智能体见 [16 智能体](16-飞书机器人智能体查询方案.md)。

当前前端路由：/mobile/task/:id、/mobile/tasks、/mobile/todo、/mobile/approve、/mobile/closures。桌面审批 /approvals 在小屏映射到 /mobile/approve；taskId、confirmId、taskLogId、at、changeId、request 等定位参数须保留。旧 plan-changes 与 closure-reports 路由是兼容入口，不再当作独立主菜单。

周进展规则辅助函数仍可能返回旧 /m/tasks/:id 格式，前端正式详情路由为 /mobile/task/:id；不能据此承诺旧辅助路径可直接访问。客户端当前使用任务标识构造的实际入口及通知链接应分别核验。

## 6. 接入验收

分别检查普通浏览器、飞书桌面、手机登录；核对身份、部门、角色、未授权用户和深链回跳。然后检查组织同步结果、个人／群通知、机器人本人／他人查询权限、模型关闭和故障回落。不要用本地模拟账号证明真实飞书触达。

没有自动 Webhook 失败切换，卡片按钮打开系统页面，不直接通过飞书回调修改业务。相关重试与通知开关见 [06 通知](06-飞书对接.md)，部署与配置见 [08 运维](08-部署与运维方案.md)。
