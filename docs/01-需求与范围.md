## 1. 系统概述

### 1.1 业务背景

公司内部项目与任务长期靠飞书多维表人工维护：一人建一张表、字段不统一、进度靠手填、延期靠人盯、没有审批留痕，总裁无法一屏掌握全公司项目状况。本系统用于**统一登记任务、驱动进度、飞书提醒、变更审批、结项留档**，替代多维表，让领导"可视化有效信息、减少决策负担"。

### 1.2 系统定位

一套面向公司各部门的**内网自部署**项目任务管理平台，覆盖从**项目立项 → 阶段子任务 → 执行推进 → 变更审批 → 完成验收 → 结项留档**的完整闭环。规模 50-300 人、十来个部门。

### 1.3 用户角色

| 角色 | 职责说明 |
|------|----------|
| 管理员（admin） | 系统配置、用户/部门角色分配、Mock 用户部门绑定、模板/分类管理、飞书同步、看全局 |
| 领导（leader） | 跨部门分派任务、查看全公司总览、按指定审批关系处理申请 |
| 部门负责人（dept_head） | 按管理范围分派和确认/退回任务；验收须符合指定验收人关系，计划变更按申请上的审批链处理 |
| 普通成员（member） | 可进入项目总览、项目/任务、用户管理等页面查看基础信息；主要推进自己参与的任务 |
| **项目负责人**（owner_id + project_owners，非角色） | 项目级字段。负责审核本项目计划变更申请、发起计划定稿（解除仅管理员）、**未定稿时新增/编辑/删除本项目任务**、**删除自己负责的未定稿项目**，可以是任意角色 |

> 任务角色术语：**执行人** = 执行任务的人（assignee）；**负责人** = 对任务结果负责/验收的人（acceptor）；两者都可多选。

### 1.4 核心流程

```
项目立项（可套模板生成阶段→子任务）
  → 计划定稿（定稿后才允许执行，之后改动走变更申请）
  → 管理角色按权限维护任务计划；普通员工仅在自己负责的项目中维护任务计划（未定稿直接编辑；定稿后走计划变更）
  → 执行人推进（待办→进行中→关键进展/过程资料→待验收→已完成，验收闭环）
  → 计划变更需申请 → 按发起人关系经项目负责人预审/总经办终审 → 最终通过才生效
  → 申请结项 → 指定总经办审批 → 固定报告及 HR 待阅（不自动计算 KPI）
```

## 2. 功能模块

### 2.1 认证与组织架构（飞书）

#### 2.1.1 登录

- 飞书自建应用 OAuth：普通浏览器和飞书桌面走网页授权；飞书手机先尝试端内免登，失败回退网页授权。系统用飞书身份签发本地 JWT。
- 本地开发/问题复现可用 Mock 登录：`FEISHU_MOCK_LOGIN=true` 只表示前端显示 Mock 入口，输入 `FEISHU_MOCK_PASSWORD` 后才能选择预设角色；它不再替代或劫持飞书 OAuth。
- 登录凭证过期后跳回登录页（401 处理）。

#### 2.1.2 组织架构同步

- 定时全量同步飞书部门与员工（默认进程时区每天 02:00），支持手动触发（「同步组织架构」按钮）。
- 用 `FEISHU_SYNC_ROOT_DEPT` 限定同步根部门分支，避免拉全公司百万数据。
- 部门/真实员工为只读缓存（来自飞书），**不做手工 CRUD**；仅管理员可分配角色（`user_roles`）。
- Mock 用户是本系统本地调试账号，在用户管理里单独分区展示；管理员只能给 Mock 用户绑定/调整部门，组织架构同步不会覆盖或删除这些账号。

#### 2.1.3 用户与权限

- 角色：admin / leader / dept_head / member（可身兼多角色）。
- 权限矩阵见 03 篇。原则：**后端守死、前端只藏按钮**。
- 所有登录用户都能看到右侧菜单中的项目总览、我的待办和用户管理；用户管理对非管理员只提供基础信息查看。
- 操作日志仍按管理权限开放，普通用户不可见；除管理员外，任何角色都不能批量分配角色或启停用户。

### 2.2 项目管理

#### 2.2.1 项目字段

| 字段 | 说明 |
|------|------|
| 项目名称 | 必填 |
| 归属部门 | 选择部门（默认当前用户部门） |
| 负责人（ownerIds） | 支持多位项目负责人，兼容 ownerId；按关系参与计划变更及结项流程 |
| 描述 / 开始日期 / 结束日期 | 可选 |
| 状态 | `active` 进行中 / `archived` 已归档 |
| **计划定稿**（plan_locked） | 定稿后任务增删改走变更申请 |

#### 2.2.2 项目操作

- **新建**：支持选模板一键生成「阶段→子任务」树并按开始日期自动排期；**归属部门可选任意部门**，部门负责人也可把项目建在其他部门下（如总经办负责人建质保部门项目）。
- **保存为模板**：把已建立项目导出为模板（结构反哺模板库）——可管理项目者（admin/leader / 部门负责人本部门 / 项目负责人）可操作；导出排除已取消任务，阶段不设工期、叶子按实际起止天数折算，新项目按此模板创建时可还原结构与排期。
- **编辑**：改名/描述/日期/负责人。当前接口仅允许 admin/leader/dept_head，且须满足部门可写或项目负责人关系；普通 member 项目负责人仍受 Controller 角色守卫限制。
- **计划定稿**：按项目管理/负责人关系校验；**解除定稿仅管理员**，结项冻结不能绕过。
- **申请结项 / 历史归档恢复**：前者由管理员或任一项目负责人申请、指定总经办审批；后者仅管理员且不能用于新结项。**删除**规则（仅**未定稿**项目可删：admin 可删任意未定稿项目，**项目负责人可删自己负责的未定稿项目**；**已定稿项目一律不可删除，含管理员，需先解除定稿**；级联删任务、前端二次确认）。

#### 2.2.3 项目状态显示（列表）

按任务启动情况计算，展示为：**未开始 / 进行中 / 已完成 / 已归档**，另显示「定稿」标签。

### 2.3 任务管理

#### 2.3.1 任务层级

- 项目下为「阶段 → 子任务」的树（`parent_id` 表达，任意层级；实际多为两级）。
- 顶层任务即"阶段/父任务"，其下是子任务，子任务下可继续挂孙任务。
- 有子任务的父任务不需要手动开始、提交验收或完成，状态和进度由子任务自动汇总；**父任务不设自身日期**，其展示时间范围 = 子任务的最早开始 ~ 最晚结束（模板生成时阶段按子任务天数之和顺排）。
- 没有子任务的任务按叶子任务处理，可以开始、填写关键进展、登记过程资料、提交验收。

#### 2.3.2 任务字段

| 字段 | 说明 |
|------|------|
| 标题 / 描述 | 任务名称和补充说明 |
| 执行人（assigneeIds） | 多选 |
| 负责人（acceptorIds） | 多选，验收人 |
| 开始 / 截止日期 | 截止不得早于开始 |
| 状态 | 见状态机 |

#### 2.3.3 任务状态机

```
pending_confirm 待确认（成员创建，待部门负责人审核）
  → todo 待办（审核通过 / 上级直接分派）
  → rejected 已退回
todo → doing 进行中
doing → pending_accept 待验收
pending_accept → done 已完成（验收通过，记 completed_at）
             → doing 退回
任意未完成态 → cancelled 已取消
```

#### 2.3.4 任务操作

- 创建、编辑、状态流转、确认/退回、改派、删除。
- **未定稿项目新增任务/子任务**：admin/leader 可在全部项目下新增，dept_head 可在自己可管理部门项目下新增；普通员工仅在自己是项目负责人的项目下新增。新增时任务负责人（acceptor）默认继承项目负责人，可按需要手动改成其他负责人。
- **项目未定稿**：任务不能开始、不能填写关键进展、不能上传过程资料、不能提交验收。
- **项目定稿后**：任务可以执行；计划性字段增删改被后端拒绝（需走变更申请）。
- **提交验收和验收通过前**：检查实际执行周次的周进展缺填与资料/无资料原因，不以仅一条进展作为充分条件。

### 2.3.5 关键进展与过程资料

- 任务详情使用“进展与资料”合并页签，一次保存工作日期、正文及文件/链接。已存在的同任务资料可以被多条进展复用，不重复计算资料份数。
- 每条进展必须有有效资料或 1–500 字无资料原因；前端关键进展输入框最多 800 字，当前后端只校验非空。工作日期、提交时间分别记录。
- 项目须已定稿且未冻结，doing/done 的有效叶子任务允许维护。电脑双栏左侧编辑区固定在视野内，长表单内部滚动。
- 提醒与验收共用规则启用后的实际 doing 区间；与工作日相交的周次需填写，验收包含本周，等待验收不新增周次。详见 [周进展](14-任务过程资料与每日进展强管控方案.md)。
- 合理补填需工作日期在截止内、原提交日期在截止后；任务分类综合全部进展，不能用单条确认覆盖其他异常。实际工作、填报和系统验收时间不得混为一谈。
- 上传限制、引用解除、修改权限和接口见 [进展与资料](14-任务过程资料与每日进展强管控方案.md)。

### 2.4 进度与风险

#### 2.4.1 进度计算（系统自动，非手填）

- 叶子任务按状态折算：done=100%、pending_accept=90%、doing=50%、其余=0%。
- 父任务（阶段）= 子任务进度等权平均；项目 = 顶层任务平均。
- 前端显示完成率环形图、每阶段进度条。
- **延期完成标识**：根据系统验收时间、任务截止及全部进展的有效合理补填依据分类；父任务递归汇总子任务风险。合理补填单列，历史无效标记不自动豁免。

#### 2.4.2 延期/临期判定

- **延期**：`due_at < 今天` 且未完成 → 红。
- **临期**：今天 ≤ due_at ≤ 今天+3天 且未完成 → 橙。
- 按叶子任务判定，向上汇总到父任务/项目/部门。

#### 2.4.3 任务管理页交互

- 默认只展开到「**部门 → 项目**」层：有延期/临期的部门保持展开露出项目行，**项目一律默认收起、不展开到任务层级**；有风险的分支置顶；
- 部门/项目/任务三套独立收起状态；操作后保留用户手动展开/收起（只初始化一次）；
- 部门/项目条显示「延期 N」「临期 N」徽标，任务行显示延期/临期标签；
- 排序：延期 > 临期 > 正常，同级按名称。

### 2.5 项目总览看板（领导视角）

- 每项目一张卡片，默认收起到“领导能一眼看懂”的摘要：当前阶段、关键剩余任务、延期/临期、父级阶段进度、预计完成时间和总进度。
- 展开后画「阶段 A→B→C」横向链：每个阶段是阶段卡片，阶段下列子任务，子任务/孙任务可继续展开；颜色含义同状态图例。
- 按**部门分组**成卡片，相邻部门一明一暗（斑马纹）；排序规则：**我的项目（我担任项目负责人 / 我执行或验收其中任务 / 项目所属部门在我所在或分管的部门）优先**，内部按 延期 > 临期 > 进行中 > 已完成；其他项目排在其后（同规则），含我的项目的部门组优先展示。**创建者不算"我的项目"**（管理员常建代建测试项目，创建 ≠ 跟进）。
- **未定稿项目**卡片带「未定稿」灰色标记，且其任务**不计入部门完成率**（未定稿项目任务尚未执行，全为 0%）。
- 每张卡有整体完成率进度条、风险徽标；点项目名下钻详情。
- 顶部汇总卡（项目总数/已完成/临期/延期）+ 颜色图例。

#### 2.5.1 我的待办工作台（全员）

- 侧边栏「我的待办」入口，所有角色可见，一次呈现"我今天要处理什么"，顶部统计条（我的待办 / 待我验收 / 我负责的项目 / 待审批变更）。
- **我的待办（执行人角度）**：我是执行人的 `待办/进行中` 任务，按项目分组，展示截止日期与延期/临期风险标；排除有子任务的父任务（父级由子任务自动汇总，不重复计）。
- **待我验收**：我是验收人、已提交待我确认的 `待验收` 任务。
- **我负责的项目**：项目负责人关系中包含我的项目（owner_id + project_owners），含完成进度。
- **待审批变更**：我有审批权的计划变更申请。
- 交互：点击「我的待办 / 待我验收」中的任务或项目 → 跳**任务管理页**并自动按该项目筛选、展开并**滚动定位高亮到该任务**（可直接 开始/提交验收/通过/退回）；点击「我负责的项目」→ 项目详情（负责人可做项目级管理）；点击「待审批变更」→ 变更审批页。不在我的待办页内做状态流转。

### 2.6 项目模板与分类管理

#### 2.6.1 项目模板

- `project_templates` 表存骨架（skeleton jsonb，`{tasks:[{title,durationDays,children}]}`）。
- 系统不再自动预置项目模板；正式环境模板以测试库迁移/人工维护为准。
- 新建项目传 `templateId` 一键生成「阶段→子任务」并按开始日期自动排期。
- **项目可反哺模板**：项目详情页「保存为模板」，把实际项目任务树导出为骨架（排除已取消；阶段不设工期、叶子按实际起止天数折算），让真实项目结构沉淀进模板库。
- 模板管理：卡片列表、新建/编辑（阶段→子任务两级编辑器，含工期）、删除。

#### 2.6.2 分类管理

- `categories` 表：名称 + 图标(emoji，点选图标库) + 主色(取色器) + 排序。
- 可增删改：**改名级联更新模板和项目**；**删除把使用该分类的模板和项目改回「未分类」**；仅「未分类」作为系统兜底分类不可删。
- 自定义分类自动配色调色板颜色。

### 2.7 计划变更审批

#### 2.7.1 触发条件

- 项目「计划定稿」后，任务**增删改**被锁定（后端拒绝 + 前端隐藏按钮）。
- 需申请的改动：改日期 / 增删任务 / 改执行人 / 改负责人。
- 不需申请（执行层）：状态流转、进度推进。

#### 2.7.2 流程

```
任务管理·项目级右侧「发起变更审核」按钮 → 弹窗编辑（不立即生效）
  → 提交生成变更申请（含 reason + items[]，可批量）
  → 待审核（原计划不动，执行不冻结）
  → 按发起人关系先项目负责人预审，再由单上总经办终审人或管理员终审
  → 通过 → 系统事务内应用全部变更 + 记 task_logs(action=plan_change)
  → 退回（附意见）→ 不变；撤销（仅发起人 + 待审核）
```

#### 2.7.3 变更项类型

| change_type | 说明 |
|-------------|------|
| date | 改开始/截止日期 |
| delete | 删除/取消任务，并从活动任务树隐藏；变更记录和操作日志保留证据 |
| add | 新增任务（task_id 可为 null=顶层，或父阶段 id=子任务） |
| assignee / acceptor | 改执行人 / 改负责人 |

#### 2.7.4 发起变更审核弹窗

- 表格式：任务 / 开始 / 截止 / 执行人 / 负责人 / 操作；执行人负责人**带出当前值**。
- 每行：改日期、改执行人/负责人、删除任务、**+ 子任务**（挂到该任务下）、**顺延后续**（输入天数，该节点及后续未删节点整体顺延）。
- 底部「+ 新增任务」加顶层任务；填变更原因后提交。

#### 2.7.5 统一审批入口

统一入口为 `/approvals`，集中展示任务确认/验收、计划变更、结项和重开；旧 `/plan-changes` 重定向至统一入口并保留查询参数。页面分类与筛选以当前审批管理界面为准。

### 2.8 结项与报告

- 管理员或任一项目负责人可申请；须已定稿、有效任务全部完成、无待审变更且项目未冻结。按部门规则前置审核后，由指定总经办终审，HR 收到报告待阅。
- 申请期间冻结，退回/撤回恢复；通过后生成固定报告。重开纠错另走审批，旧报告失效留存；历史归档恢复仅管理员。
- HTML 报告已实现查看/导出，附件独立鉴权。批准记录、工作日期、填报日期分别列示，不自动作奖惩决定。
- 四部分绿色报告模板与背景/目标/成果表单已接入，立项书解析仅辅助背景和目标填写，见 [模板状态](21-项目结项推送人力资源部（奖惩报备）方案.md)。KPI 评分及 Excel 导出未实现。

### 2.9 飞书对接

- **登录**：浏览器及飞书桌面使用网页 OAuth；飞书手机尝试端内免登，失败回退 OAuth。
- **组织架构**：定时全量同步。
- **通知**：用自建应用消息精准 @ 人。项目创建不通知；项目计划定稿后发汇总卡片；计划变更提交/通过/退回、任务提交验收/验收通过/退回、临期/延期风险发卡片式提醒。
- **定稿通知**：项目负责人收到 1 条“项目计划已定稿”汇总卡片，包含项目名称、任务总数、责任人覆盖人数、已过期任务数、3 天内临期任务数、前 5 条风险任务。
- **任务相关人通知**：定稿后给任务执行人和任务负责人发个人汇总卡片，列出需要执行/负责验收的任务及延期项；同一人同时是项目负责人时合并发送，避免刷屏。
- **每日个人汇总卡**：工作日 09:10、13:10 按人汇总待办、待验收、项目风险、待审批及缺填周进展等事项。待办中进行中任务可进入提醒；未开始任务按开始日期与风险过滤。同日同 slot 去重，精确筛选及节假日规则见 [飞书对接](06-飞书对接.md)。事件型通知即时触发。

### 2.10 工作日报与审批历史

工作日报按北京时间的原始提交时间 created_at 汇总，默认上一个工作日；工作日期 work_date 单独显示，不能把补填误当成当天完成。网页仅 admin 或当前总经办接收人可看，普通 leader/dept_head 身份本身不授予权限。读取日报成功后按用户与日期记录已读，未读从首次可见日期开始，不依赖本机浏览器缓存。

审批管理支持待我审批、我已审批、我发起的、与我相关。历史任务审批以 task_logs 的具体轮次定位，不以当前任务状态改写旧结论；取消任务的计划变更仍按参与关系及变更快照判定可见性。操作日志区分申请人和实际审核人，未审批的申请不伪造审核结果。

## 3. 合规与安全要求

### 3.1 编辑留痕、可追溯、查询直观

- 所有增删改（不只状态流转）写 `task_logs`：操作人、时间、变更前后值。
- 任何实体可查完整操作历史（时间线），详情随任务/项目一起展示。
- 列表多维筛选（部门/项目/状态/执行人/时间区间）+ 全局搜索。

### 3.2 可视化有效信息，减少领导决策

- 红黄绿信号统一（延期=红、临期=橙、完成=绿、进行中=蓝、未开始=灰）。
- 风险优先、过程弱化：延期/临期排最前，健康数据收起。
- 总览优先于明细、默认收起重点自动展开、一屏决策、少即是多。

### 3.3 数据与权限

- 应用及数据库可内网自部署；通知和组织架构对接飞书。启用外部 LLM 时可能发送查询所需业务数据，须按环境配置及公司要求管理。
- 后端守死权限、前端只藏按钮；所有登录用户可进入项目总览、项目/任务、用户管理查看基础信息，编辑权按角色/参与关系/项目负责人/部门负责人收敛。
- 普通用户不可见全局操作日志；除管理员外不能进行角色批量分配、用户启停和真实用户角色维护。
- 归档后只读冻结；已放行/归档数据不可改。

## 4. 业务规则汇总

| 编号 | 规则描述 |
|------|---------|
| BR-01 | 未定稿项目新增任务/子任务：admin/leader 可全局新增，dept_head 可在可管理部门新增，普通员工仅限自己负责的项目；任务负责人默认继承项目负责人，可手动调整 |
| BR-02 | 项目创建不发送飞书通知；项目计划定稿后才向项目负责人和任务相关人发送汇总卡片 |

| BR-04 | 进度系统自动算（子任务进度汇总），禁止手填任务总进度 |
| BR-05 | 叶子任务进度=按状态折算，父任务=子任务等权平均，项目=顶层平均 |
| BR-06 | 延期=截止已过且未完成；临期=3 天内到期且未完成 |
| BR-07 | 项目未定稿时任务不可执行；必须先计划定稿，才能开始任务、填关键进展、上传资料或提交验收 |
| BR-08 | 计划变更申请必须填变更原因 |
| BR-09 | 变更申请待审核期间执行不冻结、原计划不动 |
| BR-10 | 变更按项目负责人预审、总经办终审的审批链处理；负责人发起可直达终审，最终通过才生效 |
| BR-11 | 变更审核通过后自动应用全部变更并记 task_logs(action=plan_change) |
| BR-12 | 变更申请仅发起人可撤销，且仅待审核状态 |
| BR-13 | 「未分类」分类不可删除；删分类时使用该分类的模板和项目改回「未分类」 |
| BR-14 | 分类改名级联更新引用该分类的模板 |
| BR-15 | 系统不再自动预置项目模板；正式环境模板以测试库迁移/人工维护为准 |
| BR-16 | 结项审批中/已结项冻结；重开走独立审批；历史归档仅管理员恢复 |
| BR-17 | 任务角色术语：执行人=assignee、负责人=acceptor（多选）；项目负责人=projects.owner_id + project_owners |
| BR-18 | 所有登录用户可进入项目总览、项目/任务、用户管理查看基础信息；部门负责人可编辑本部门（含可管理部门）；项目负责人可编辑/删除本项目任务（未定稿） |
| BR-19 | 前端按角色+数据范围隐藏按钮，后端接口为权限最终校验 |
| BR-20 | 有子任务的父任务不手动流转，由子任务状态自动汇总 |
| BR-21 | 叶子任务提交验收与验收通过均核查实际执行周次的周进展、资料或无资料原因 |
| BR-22 | 本地文件与飞书/链接资料都必须关联到某天关键进展 |
| BR-23 | 操作日志必须显示操作人，便于运维排查 |
| BR-24 | Mock 用户只用于问题复现，独立于飞书同步；管理员可在用户管理中维护其部门绑定 |
| BR-25 | 工作日 09:10、13:10 按人发送个人汇总，按 slot 去重；待办筛选、周进展和项目风险规则见 06 篇 |
| BR-26 | 创建项目时「归属部门」可选任意部门，部门负责人可跨部门建项目；创建后的管理权由项目负责人/该部门负责人决定 |
| BR-27 | 仅未定稿项目可删除：管理员可删任意未定稿项目，项目负责人可删自己负责的未定稿项目（级联删任务、前端二次确认）；已定稿项目一律不可删除（含管理员，需先解除定稿再删），领导无全项目删除权 |

## 5. 附录：示例业务流

### 5.1 未定稿项目新增任务

```
有新增权限的人在未定稿项目下新增任务/子任务
  → 任务负责人默认带入项目负责人
  → 如需其他验收负责人，再手动调整负责人
  → 项目计划定稿后，任务进入可执行状态
```

### 5.2 计划变更（延期场景）

```
项目计划定稿 → 中间节点需延后
  → 任务管理里点「发起变更审核」
  → 选中该节点点「顺延后续」，输入 N 天 → 该节点及后续节点日期整体顺延
  → 填变更原因 → 提交
  → 按审批链处理预审及终审，最终通过后应用计划
  → 系统自动应用全部日期变更，原值→新值记入操作日志
```
