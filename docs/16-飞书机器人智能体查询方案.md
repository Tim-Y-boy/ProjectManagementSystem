# 16 · 机器人智能体查询

核对日期：2026-10-27。描述当前 bot 模块实现，不使用旧 P0/P1 分期计划或响应时间示例作为交付证明。

## 1. 处理流程

长连接接收消息 → 映射本地启用用户 → 关键词查询，或在模型启用且已配置密钥时先回复“正在查询…” → AgentService 调用模型选择只读工具 → 工具按请求者权限查询 → 结果交模型组织为纯文本 → 异步发送结果并记录日志。

模型不会直接访问数据库，工具不提供审批、改任务或代填进展。工具返回为空或权限不足时应如实转达，最终权限来自后端，不能靠提示词放行。

## 2. 当前工具

| 工具 | 用途及范围 |
|---|---|
| query_my_tasks | 本人的任务 |
| query_due_tasks | 本人今天／本周到期窗口 |
| query_project_progress | 指定进行中项目进度 |
| get_project_summary | 指定进行中项目汇总 |
| query_all_projects | 当前进行中项目清单，按项目读取规则 |
| query_overdue_tasks | mine/dept/all；部门与全局查询要求对应管理权限 |
| query_pending_reviews | 待本人审核的计划变更，不等同于网页全部审批类型 |
| query_my_projects | 本人参与项目 |
| search_projects | 项目名称搜索 |
| search_users | 用户基础信息搜索 |
| query_user_tasks | 本人，或有权管理的部门／全局人员 |
| help | 当前查询帮助 |

工具实际参数定义在 [agent-tools.ts](../server/src/modules/bot/agent-tools.ts)，数据权限和结果限制在 [bot-query.service.ts](../server/src/modules/bot/bot-query.service.ts)。项目基础信息可见与查询他人任务不是同一权限。

“所有项目”调用 query_all_projects，不把宽泛词当成项目名；复合问题可多轮调用工具，但受轮数预算限制。回复采用纯文本，不依赖 Markdown 表格或富卡片展示。

## 3. 配置与预算

| 配置 | 默认 | 用途 |
|---|---|---|
| LLM_ENABLED | false | 开启智能体及相关模型能力 |
| LLM_BASE_URL | https://api.deepseek.com/v1 | 当前适配器在其后添加 /chat/completions |
| LLM_API_KEY | 空 | 模型密钥，不写入代码或文档 |
| LLM_MODEL | deepseek-chat | 模型名 |
| LLM_TIMEOUT_MS | 10000 | 单次请求超时毫秒 |
| LLM_MAX_TOKENS | 1500 | 输出预算 |
| LLM_MAX_ROUNDS | 4 | 模型交互轮次上限，至少 1 |

OpenAiCompatLlmAdapter 发送 messages、tools、temperature=0 和 max_tokens，解析 choices[0].message 的 content/tool_calls。只兼容该协议契约，不能承诺切换任意供应商只改地址即可工作。机器人适配器未统一发送 thinking/reasoning_effort；项目群简报在 TasksService 使用独立的 LLM_BRIEF_* 参数。

单条工具结果截断到 2000 字符，历史问答按 BotQueryService.recentConversations 读取；持久化 bot_conversation 支持追问，但不等于永久无损记忆或附件 RAG。

## 4. 失败、日志与状态

not_configured、timeout、network、http、bad_response、empty、tool 类型的 LlmError 会触发关键词回落；其他异常返回通用错误。轮数耗尽返回“问题太复杂”的提示，不再继续调用。未知工具或错误参数先反馈给模型纠正，工具数据库异常进入失败处理。

bot_query_logs 保存查询日志，agent_trace 保存调用追踪，bot_conversation 保存问答。发送“正在查询…”失败会记录日志，后台仍尝试查询；不承诺 1 秒内收到或所有网络情况下必达。

## 5. 验证与边界

以合成项目和用户验证本人／他人权限、空结果、宽泛问法、明确项目名、复合查询、上下文指代、模型关闭、超时、坏响应与轮数上限。模型收到的查询、上下文和工具结果会发送到配置的模型服务，启用前按自己的数据使用规则配置。

当前不提供自动写操作、附件向量检索、流式答复或以模型判断替代业务审批。立项文件解析复用模型配置，但由 closures 模块独立执行，见 [结项与报备](21-项目结项推送人力资源部（奖惩报备）方案.md)。
