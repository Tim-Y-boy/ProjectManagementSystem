# 12 · 计划变更审批

更新日期：2026-10-27。当前本地实现为两级审批；以部署版本判定线上能力。

## 1. 已确认口径

1. **定稿**：方案 A —— 项目加「计划定稿」动作。定稿后锁日期/范围等关键字段，改动走申请；定稿前自由编辑。
2. **需申请的改动**：改日期、增删任务、改执行人、改负责人、调整顺序。**不需申请**（执行层）：状态流转、进度推进。
3. **两级审批链**：
   - 判定只按「发起人是不是该项目负责人」：
     - **项目任一负责人发起** → 直接到**总经办负责人**终审；
     - **其它人发起**（执行人/普通成员/部门负责人/admin/领导，只要不是该项目负责人）→ **先经项目负责人**，负责人通过后再到**总经办负责人**终审；
     - 项目**无负责人** → 直接总经办终审；
     - 负责人即总经办负责人（同一人）→ 只终审一次。
   - **终审人** = 总经办部门（名称"总经办"）的负责人，可用 PLAN_FINAL_APPROVER_USER_ID 显式覆盖；否则找不到部门负责人时优先启用 admin，再选 leader（按 ID 排序）；终审操作允许"单上终审人 + 管理员"，**不放开给其它领导**。
   - 任一级退回 → 整单退回，发起人可见退回级与意见，可改后重提。
4. **发起权限**：项目负责人 / 可管理该项目的角色 / **项目任务执行人**（assignee）均可发起。
5. **存量单**：升级前已存在的 pending 单仍按原单级规则审批（final_approver_id 为空判定为存量单）。
6. **粒度**：支持**批量**（一次申请多任务）；支持「中间节点延后 → 后续节点连带顺延」。

## 2. 术语（任务角色）

- **执行人** = 执行任务的人（`assignee` / `task_assignees.role='assignee'`）
- **负责人（任务）** = 对任务结果负责/验收的人（`acceptor` / `task_assignees.role='acceptor'`）
- 项目层面的**「项目负责人」**是 `projects.owner_id` 与 `project_owners` 的多人关系；两者不同，注意区分——审批链用的是「项目负责人」。

## 3. 流程

```
项目「计划定稿」→ 之后任务增删改被锁（改日期/执行人/负责人/增删任务/调序 需走申请）
发起申请（任务管理·项目级右侧「发起变更审核」→ 弹窗编辑，不立即生效）
   │
   ├─ 发起人 = 项目负责人 → 直接 待总经办负责人终审
   └─ 其它人（含执行人/admin/领导/部门负责人 非该项目负责人）
          → ① 待项目负责人审核
                ├─ 通过 → ② 待总经办负责人终审
                └─ 退回 → 整单退回（发起人可见，可改后重提）
   └─（项目无负责人 → 直接待总经办终审）
   └─ ② 总经办负责人终审
          ├─ 通过 → 系统事务内应用全部变更 + 记 task_logs(action=plan_change) + 通知发起人
          └─ 退回 → 整单退回
   发起人可随时撤销（仅 pending）
```

**关键原则**：未定稿项目计划可调整但任务不可开始执行；已定稿项目执行不冻结（状态流转照常），仅"计划字段"被锁；定稿项目的任务增删改后端拒绝（需走申请）；变更**全部审批通过后**才把计划改动真正应用到任务（负责人级通过不立即生效）。

## 4. 数据模型

### Project

| 字段 | 类型 | 说明 |
|---|---|---|
| owner_id | bigint null | 主负责人兼容字段；多人权限结合 project_owners |
| plan_locked | bool default false | 计划是否已定稿 |

### `plan_changes`（变更申请单，迁移 1788400000000 新增审批链字段）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | |
| project_id | bigint FK | 所属项目 |
| reason | text | 变更原因（必填） |
| requester_id | bigint FK | 发起人 |
| approver_id | bigint FK null | 终审人/退回人（写入时） |
| approver_comment | text null | 终审/退回意见 |
| status | varchar | pending / approved / rejected / cancelled |
| **stage** | varchar default final | 当前待审批级：`owner`（待项目负责人） / `final`（待总经办终审） |
| **final_approver_id** | bigint null | 终审人（提交时解析"总经办负责人"，存量单为空） |
| **owner_approver_id** | bigint null | 第 1 级项目负责人（通过时写入，发起人可见） |
| **owner_approved_at** | timestamptz null | 第 1 级通过时间 |
| **owner_comment** | text null | 第 1 级意见 |
| **rejected_stage** | varchar null | 若被退回，记录退回发生在哪一级（owner/final） |
| created_at / reviewed_at | timestamptz | |

`plan_changes.final_approver_id IS NULL` = 存量单（升级前），审批仍按原单级。

### `plan_change_items`（变更项，支持批量）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | |
| change_id | bigint FK | 关联申请单 |
| task_id | bigint FK null | 目标任务；`add` 类型可为 null（顶层）或父阶段 id |
| change_type | varchar | date / add / delete / assignee / acceptor / reorder |
| before | jsonb | 原值快照 |
| after | jsonb | 拟变更值 |

终审通过时逐项应用：`date`→改起止、`delete`→取消任务并从活动树隐藏、`add`→新建任务（可挂顶层/任意父任务）、`assignee`/`acceptor`→改执行人/负责人、`reorder`→调整顺序；每项记 `task_logs`。旧遗留类型 priority/deliverable 仅在历史记录中出现，前端隐藏。

## 5. 接口

| Method | Path | 权限 | 说明 |
|---|---|---|---|
| POST | `/projects/:id/plan-lock` | 项目负责人/dept_head(本部门)/leader/admin | 定稿 / 解除定稿（解除定稿仅管理员，body `{locked}`） |
| POST | `/plan-changes` | 项目可管理角色/项目执行人 | 发起申请（提交时按发起人定审批级与终审人） |
| GET | `/plan-changes` | 按可见性 | 列表，含 projectName/projectOwnerId/projectDeptId/stage/finalApproverId 等 |
| GET | `/plan-changes/:id` | 按可见性 | 详情（items、审批轨迹字段） |
| POST | `/plan-changes/:id/approve` | **仅当前级**：owner 级=项目负责人；final 级=终审人(总经办负责人)或管理员 | 通过（owner 级仅推进到终审；final 级才应用变更） |
| POST | `/plan-changes/:id/reject` | 同上 | 退回（附意见，记录 rejected_stage） |
| DELETE | `/plan-changes/:id` | 发起人 | 撤销（仅 pending） |

## 6. 前端

- **项目列表**：新建/编辑项目可指定「项目负责人」；操作列「定稿/解除定稿」；状态列显示「未开始/进行中/已完成」+「定稿」标签。
- **任务管理**：定稿项目任务加「已定稿」标签，编辑/+子任务/删除隐藏；项目级右侧「发起变更审核」。
- **发起变更审核弹窗**：表格式编辑（任务/开始/截止/执行人/负责人/操作），支持改日期/改人/删除/+子任务（含子任务下再新增）、顺延后续、新增顶层任务；填原因提交后**不立即生效**。
- **变更审批页**（待我审核 / 审批历史 / 我发起的）：
  - 待审状态区分「**待项目负责人** / **待总经办终审**」；
  - 详情展示**审批轨迹**：第 1 级（项目负责人）与第 2 级（总经办负责人）各显示 ✅已通过 / ⏳待审批 / ❌已退回 + 审批人 + 时间 + 意见，发起人与审批人均可见；
  - 只有**当前级**审批人能看到通过/退回按钮（owner 级=项目负责人；final 级=总经办负责人或管理员）。

## 7. 与结项流程的区别

计划变更终审允许单上终审人或管理员；结项前置审核仅允许单上对应部门负责人，终审仅允许单上指定总经办审批人。结项可由管理员或任一项目负责人申请，申请后冻结项目；时间差异自动留档，不再强制填写迟申请原因。完整流程见 [结项与报备](21-项目结项推送人力资源部（奖惩报备）方案.md)。


## 8. 当前入口与历史定位

审批页统一为 /approvals，手机为 /mobile/approve；旧 /plan-changes 及手机对应路径重定向，保留 changeId 与查询参数。计划变更 API 仍是 /api/plan-changes，页面迁移不意味着接口路径改名。

“与我相关”结合项目负责人、当前任务参与者以及变更前后快照判定，不因任务被取消就丢失其审批记录。操作日志分开展示发起人与实际审核人及各自时间；仅提交申请不算已审批。
