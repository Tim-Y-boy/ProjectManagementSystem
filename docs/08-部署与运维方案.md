# 08 · 部署与运维

核对日期：2026-10-27。依据 Dockerfile、docker-compose.yml、环境示例、TypeORM 配置及定时任务源码；本文不宣称任何服务器已发布。早期服务器实录不再作为当前部署步骤。

## 1. 目录与服务

| 内容 | 位置与用途 |
|---|---|
| 前端 | web，Vue 3 / Vite，开发端口 5173 |
| 后端 | server，NestJS / TypeORM，默认端口 8081，接口前缀 /api |
| 数据库 | PostgreSQL 15；Compose 内地址 db:5432，宿主机绑定 127.0.0.1:5433 |
| 网页容器 | Nginx，宿主机 8088；/api 代理 api:8081 |
| 资料 | Compose 将根目录 uploads 挂载到 /app/uploads；包括任务资料和 closure-charters |
| 日志 | Compose 将 logs/api 挂载到 /app/logs |
| 数据卷 | db_data，不能把源码归档当成数据库备份 |

## 2. 配置来源

本地后端在 server 目录启动，使用 server/.env；Compose 在仓库根目录启动，使用根目录 .env。示例文件不是实际运行配置。端口与地址应显式填写，避免旧默认回调端口与本环境不一致。

| 配置 | 说明 |
|---|---|
| POSTGRES_DB / POSTGRES_USER / POSTGRES_PASSWORD | Compose 数据库初始化；API 的 DB_* 由 Compose environment 覆盖为对应值 |
| DB_HOST / DB_PORT / DB_USERNAME / DB_PASSWORD / DB_DATABASE | 本地后端与测试数据库连接 |
| JWT_SECRET | 使用自行生成的随机密钥，不沿用示例值 |
| JWT_AUTH_EXPIRES / JWT_REFRESH_EXPIRES | config.ts 实际读取的过期配置；示例里的 JWT_ACCESS_EXPIRES 不替代 JWT_AUTH_EXPIRES |
| FEISHU_APP_ID / FEISHU_APP_SECRET | 本环境自建应用凭据 |
| FEISHU_REDIRECT_URI / WEB_FRONT_URL | OAuth 完整回调地址与用户可访问的网页根地址 |
| FEISHU_MOCK_LOGIN / FEISHU_MOCK_PASSWORD | 调试入口；生产同时关闭开关、清空密码，不依赖代码默认值 |
| FEISHU_ADMIN_USER_IDS | 初始管理员飞书身份，逗号分隔，不在公开文档写真实值 |
| FEISHU_NOTIFY_DISABLED / FEISHU_GROUP_NOTIFY_DISABLED | 禁止真实通知／群通知 |
| FEISHU_NOTIFY_REDIRECT_USER_ID | 测试个人通知转发，仅改变投递对象，不改变审批身份 |
| FEISHU_BOT_ENABLED / FEISHU_BRIEF_GROUP_CHAT_ID | 长连接机器人与项目简报目标群 |
| FEISHU_BRIEF_FONT_PATH | 可选中文字体路径；Dockerfile 安装 fonts-noto-cjk |
| PLAN_FINAL_APPROVER_USER_ID / PROJECT_GM_DEPT_NAME | 结项终审人解析配置；计划变更的部门回退仍按其服务逻辑处理 |
| PROJECT_HR_NOTIFY_USER_ID / PROJECT_HR_DEPT_NAME | HR 报告、延期日报接收人 |
| LLM_ENABLED / LLM_BASE_URL / LLM_API_KEY / LLM_MODEL | 可选模型；默认关闭，配置见智能体说明 |
| LLM_TIMEOUT_MS / LLM_MAX_TOKENS / LLM_MAX_ROUNDS | 单次调用与工具循环预算 |
| LLM_BRIEF_THINKING / LLM_BRIEF_MODEL / LLM_BRIEF_MAX_TOKENS / LLM_BRIEF_TIMEOUT_MS | 项目群简报的模型参数，区别于机器人适配器 |
| LOG_DIR / LOG_MAX_SIZE_MB / LOG_RETENTION_DAYS / ERROR_LOG_RETENTION_DAYS / SLOW_REQUEST_MS | 运行日志位置、轮换和慢请求阈值 |

修改 Compose 的 env_file 后重建 API 容器，使新环境进入容器；仅重启旧容器不保证读取新 env_file。不要把完整 printenv、令牌或业务正文粘到排障文档。

## 3. 本地开发与构建

准备 PostgreSQL，复制 server/.env.example 为 server/.env 并填自己的连接配置。后端启动即执行未应用迁移，确认目标为开发数据库。

~~~powershell
npm.cmd ci --prefix server
npm.cmd ci --prefix web
npm.cmd run dev --prefix server
~~~

另开终端运行 npm.cmd run dev --prefix web。前端 /api 代理到 localhost:8081。

发布前在源码根目录构建：

~~~powershell
npm.cmd run build --prefix server
npm.cmd run build --prefix web
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 api
~~~

Dockerfile 复制已构建的 dist，Compose 不从源码自动编译 TypeScript。上传发布包时包含 Dockerfile、Compose、依赖清单、server/dist、web/dist 及 Nginx 配置；服务器 .env 和数据单独保留。

## 4. 迁移与首次配置

typeOrmConfig 设置 migrationsRun=true，启动会执行 migrations 表中尚未应用的迁移；DB_SYNCHRONIZE 保持关闭，不使用 synchronize 代替迁移。完整列表见 [数据库设计](04-数据库设计.md)。

归档版本必须包含 AddClosureIntelligence、AddClosureAnalysisScopeIdentity、UnifyWeeklyProgressWindow、AddDailyReportReads 等后续迁移，不能仅部署旧基线。规则配置、人员与组织映射在本环境维护；扫描立项书暂不支持 OCR。旧申请仍按提交时快照处理。

上线核对：部门和人员同步、初始管理员、项目终审人、HR 接收人、结项审核规则映射、工作日历、可访问的前端入口、文件持久化及中文字体。

## 5. 备份与恢复

备份至少包含数据库逻辑备份、uploads 全目录、实际配置的受控副本和对应应用版本。数据库备份记录时间与校验值，并在隔离数据库验证能恢复。生产与备份凭据不进入 Git。

PostgreSQL 可通过 pg_dump 的 custom 格式输出到容器内文件，再用 docker compose cp 复制出来，避免 Windows PowerShell 文本重定向破坏二进制备份。示例仅在配置正确的部署目录执行：

~~~sh
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc -f /tmp/project-backup.dump'
docker compose cp db:/tmp/project-backup.dump ./project-backup.dump
~~~

恢复时先停止业务写入，选择匹配的数据库、uploads 和应用版本；先在独立数据库使用 pg_restore 验证，再按环境切换。不要未经核对执行清库、DROP SCHEMA 或旧专项修复 SQL。HTML 报告不包含上传附件本体。

## 6. 调度与排障

业务提醒按 Asia/Shanghai；组织同步的 02:00 Cron 未显式指定时区，受进程时区影响，部署时核对。工作日规则由 holidays 覆盖；周五周进展提醒遇节假日跳过，不顺延。详细调度见 [飞书通知](06-飞书对接.md)。

| 问题 | 检查 |
|---|---|
| 网页正常但 API 失败 | api 启动、Nginx /api 代理、DB 连接及迁移日志 |
| 手机打不开消息链接 | WEB_FRONT_URL 是否对手机网络可达；不能使用电脑 localhost |
| OAuth 回调失败 | 回调协议、域名、端口、路径与应用配置完全一致 |
| 简报图表缺字 | 容器中文字体或 FEISHU_BRIEF_FONT_PATH；修改镜像后重建 API |
| 通知收件人不符 | 身份映射、单上审批人、HR/GM 配置及测试转发开关 |
| 解析结果过期 | 配置版本、文件、提交人或负责人变化后重新解析／确认 |
| 周验收缺填 | 实际执行区间、启用时间、工作日历和 work_date；不按旧计划区间补造记录 |
