# 17-前端视觉规范

## 文档信息

| 项目 | 说明 |
|------|------|
| 文档版本 | 当前实现与设计约定核对版 |
| 更新日期 | 2026-10-27 |
| 更新说明 | 对齐主题变量、现有导航、审批历史、日报提醒及报告；推荐值不代表所有局部组件已统一 |

> 适用范围：项目任务追踪系统，以及后续同系列内部业务系统。
> 核心目标：界面要简约、耐看、低噪音；用户打开页面后，第一眼能看到重点风险、当前进度和自己要处理的事项。

## 1. 整体风格定位

系统视觉方向采用”低饱和主题青 + 白色业务卡片 + 克制状态色”。

关键词：

- 简约：减少装饰性渐变、流光、大面积高饱和色块。
- 耐看：主题青要偏沉稳，不要荧光、不偏亮。
- 层级清楚：部门 / 类别、项目、父任务、子任务必须一眼分开。
- 重点突出：延期、临期、待处理事项优先展示；重复统计和低价值辅助文字要收掉。
- 同系统一致：登录页、左侧导航、看板、表格、弹窗、模板页都使用同一套颜色和组件气质。

## 3. 颜色规范

| 用途 | 推荐颜色 | 使用说明 |
| --- | --- | --- |
| 品牌主色 | `#288174` | 主按钮、选中态、重点边框、当前层级标识 |
| 品牌深色 | `#237266` / `#1e6258` | hover、重点文字、左侧导航文字 |
| 品牌浅底 | `#ecf4f2` / `#f9fbfb` | 页面浅绿背景、选中底色、提示区 |
| 完成 / 成功 | `#288174` | 已完成、成功、完成率 |
| 进行中 | `#288174` | 看板阶段进行中、进度条；任务行 badge 用蓝 `#1e6fd9`（语义区分） |
| 信息提示 | `#5a749b` | info 语义色，仅中性提示用，不用于状态动作 |
| 临期 / 提醒 | `#bd8433` | 3 天内到期、待关注、提醒 |
| 延期 / 危险 | `#b9555b` | 延期、删除、退回、失败 |
| 辅助紫 | `#7b6ca1` | 子任务数量、次要分类标签，不要大面积使用 |
| 主文字 | `#17211c` | 页面标题、项目名、任务名 |
| 次级文字 | `#5c6a63` | 执行人、负责人、日期等元信息 |
| 弱文字 | `#7d8a84` | placeholder、弱提示、空状态补充说明 |
| 边框 | `#e4e7e5` / `#eef1ef` | 表格线、卡片边框、分割线 |

注意：

- 主色为低饱和主题青 `#288174`，避免高饱和青 `#0d9488` 大面积铺开。
- 不要随手新增相近绿色；如果确实需要新色，先判断是否有新的业务语义。
- 风险色只用于状态表达，不要把整块页面染红或染橙。

## 4. 状态表达规范

| 状态 | 文案 | 颜色 | 推荐表达 |
| --- | --- | --- | --- |
| 未开始 | 未开始 / 待办 | 灰色 | 灰色圆点 + 灰色标签 |
| 未定稿 | 未定稿 | 橙黄（warning） | 橙黄标签；项目卡片标识，且不计入完成率 |
| 进行中 | 进行中 | 主题青 / 蓝 | 看板阶段青圆点+青进度条；任务行 badge 蓝 |
| 待验收 | 待验收 | 主题青或提醒色 | 业务待处理标签 |
| 已完成 | 已完成 | 主题青 | 青标签 / 青进度（与品牌主色同相） |
| 延期完成 | 延期完成 ⚠️ | 低饱和红 | 基于系统验收与日期依据分类；有效合理补填单列，不用单条标记覆盖整任务 |
| 临期 | 临期 / 剩 X 天 | 橙棕 | 标签 + 天数 |
| 延期 | 延期 / 延期 X 天 | 低饱和红 | 标签 + 天数，必须醒目 |
| 已取消 | 已取消 | 灰色 | 尽量隐藏在非核心列表；如需显示，弱化处理 |

风险信息必须同时给出“状态 + 天数”。例如：

```text
延期 4 天
剩 2 天
```

不要只给一个红点或橙点让用户猜含义。

## 5. 页面骨架规范

### 5.1 左侧导航

左侧导航采用白色，不再使用深色大渐变，也不铺大面积浅绿。

推荐：

- 背景：`#ffffff`（纯白）
- Logo 区：去掉浅绿实心块，保留 logo 图 + 中性描边
- active：`#d5e7e2`（浅青药丸）+ 主题青文字
- hover：`#f1f5f2`（中性浅灰）
- 文字：`#2b3a33`（中性墨）
- 导航项高度约 `42px`，圆角 `14px`

导航菜单要稳定，不要因为不同页面切换出现样式跳变。当前导航为项目总览、工作日报（有权用户）、我的待办、审批管理、项目任务、结项审批、操作日志、模板管理、用户管理、组织架构、工作日历；分组项不单独跳转，角色与业务权限按 NavMenu 和路由校验。旧归档／报告链接重定向，不再当独立菜单。

### 5.2 顶部栏

- 高度：`56px`
- 背景：白色或极浅绿白色
- 标题放左侧，用户信息和同步按钮放右侧
- 用户名、角色标签如有省略，必须加 hover 完整显示

### 5.3 登录页

登录页必须和系统内页统一：

- 使用近白中性页面背景：`#f5f7f6`
- 可以有非常轻的网格或光斑，但不要回到深蓝黑背景
- 登录卡片使用白底、`24px` 圆角、轻阴影
- 主按钮使用 `#288174`
- Mock 登录区域是调试入口，视觉上弱于飞书登录，默认不抢主流程

## 6. 卡片规范

通用卡片：

```css
.page-card {
  background: #fff;
  border: 1px solid #e4e7e5;
  border-radius: 20px;
  box-shadow: 0 1px 2px rgba(15, 23, 42, 0.04);
  padding: 20px;
}
```

规则：

- 普通承载卡片用白底、细边框、轻阴影。
- 层级卡片可以用左侧细导线、轻缩进、浅色标签表达关系。
- 风险卡片用浅红底和红色文字，不用大面积纯红。
- hover 可以轻微上浮 `1px`，不要有强烈动画。
- 看板卡片里不要堆太多统计，优先展示“进度 + 当前风险 + 关键剩余”。

## 7. 按钮规范

| 类型 | 样式 | 使用场景 |
| --- | --- | --- |
| 主按钮 | 低饱和主题青实心 | 创建、保存、提交、确认 |
| 次按钮 | 白底灰边 | 取消、关闭、刷新 |
| 文字按钮 | 主题青或中性灰文字 | 详情、编辑、打开 |
| 危险按钮 | 红色文字或浅红底 | 删除、退回、失败操作 |
| 警告按钮 | 橙棕色 | 发起审核、定稿、临期相关操作 |

按钮原则：

- 一个区域只保留一个最强主按钮。
- 行内操作优先用文字按钮，不要一排彩色实心按钮。
- 删除类操作始终靠后，并使用危险色。
- 按钮颜色饱和度要和主色统一，不要出现刺眼蓝、亮绿、亮红。

## 8. 表格与日志列表规范

表格建议：

```css
.el-table {
  --el-table-border-color: #e7eae8;
  --el-table-header-bg-color: #f8f9f8;
  --el-table-header-text-color: #5c6a63;
  --el-table-row-hover-bg-color: #f3f6f4;
  border-radius: 12px;
}
```

操作日志规则：

- 默认不展示所有项目日志，应提示用户“请选择具体项目后查看日志”。
- 选择项目后再查询该项目日志。
- 支持动作类型和时间段筛选。
- 时间范围控件不要过长；不选时分时，默认按选择日期的 `00:00` 处理。
- 使用分页；当前日志表有 460px 最大高度，不能把“无内部滚动”写作已实现标准。
- 日志表格左侧加序号列，方便沟通“第几条记录”。
- 文本过长允许省略，但必须 hover 显示完整内容。

## 9. 筛选区规范

筛选区使用浅背景容器：

```css
.filter-panel {
  background: #f7f9f8;
  border: 1px solid #e4e7e5;
  border-radius: 12px;
  padding: 14px 18px;
}
```

规则：

- 控件高度保持一致，通常 `36px ~ 40px`。
- 查询条件按业务重要性从左到右排列。
- 开关按钮必须配文字说明，例如“仅显示我参与的”，不能只放一个无说明 switch。
- 默认查询不要一次性拉全量数据；长列表使用分页。

## 10. 项目总览看板规范

项目总览是领导最常看的页面，原则是“看风险，不看流水账”。

推荐层级：

```text
部门 / 类别
  └─ 项目
      └─ 父级任务阶段
          └─ 子任务 / 孙任务
```

### 10.1 顶部总览

顶部只展示全局关键指标：

- 项目总数
- 已全部完成
- 临期项目
- 延期项目
- 状态图例
- 看板切换：看板视图 / 按部门 / 按类别

不要在顶部加入过多明细，避免信息密度过高。

### 10.2 部门 / 类别分组

部门或类别标题行应展示：

- 类型标签：部门 / 类别
- 名称
- 项目数
- 延期 / 临期 / 完成等关键标签
- 部门视图下可展示完成率
- 部门视图下可展示一条最重要风险，例如：`重点：现有巡检流程梳理 延期 4 天`

不要在分组标题里重复堆“任务 1/16、延期 1、临期 0、延期清单...”这类长串统计。完整明细应该放到展开区域或详情页。

### 10.3 项目卡片

项目卡片应突出：

- 项目名称
- 项目状态 / 风险标签
- 关键剩余任务
- 总进度
- 延期和临期数量

可以省略的辅助信息：

- “父级任务阶段 X 项”这类标题
- “父级任务 0/4｜任务完成 1/16｜剩余 15｜当前...”这类和卡片信息重复的底部说明

### 10.4 阶段卡片

父级任务阶段卡片要保留，但不需要额外标题说明。

阶段卡片建议展示：

- 阶段名称
- 完成率
- 预计完成日期
- 小进度条

阶段名称省略时必须加 hover 完整显示。

### 10.5 深层任务展开

如果点击项目下拉展开完整任务链路：

- 用左侧竖线和横向连接线表示层级。
- 父任务比子任务更粗、更大。
- 子任务向右缩进，字号略小。
- 负责人放前面，执行人放后面。
- 延期天数必须直接露出，不要让用户去找颜色含义。

## 11. 任务列表规范

任务列表是执行页面，信息应围绕“谁负责、谁执行、什么时候完成、现在风险是什么”。

规则：

- 项目未定稿时，任务允许拖动排序。
- 模板编辑时，阶段和子任务也允许拖动排序。
- 新建任务后，同一个父级任务下应自动按截止日期从早到晚排序。
- 父级任务的执行人不手填，优先由子任务执行人自动统计。
- 父级任务不需要展示交付物和优先级这类低频字段。
- 交付成果应通过“关键进展 + 过程资料”记录，不放在新建任务主表单里增加负担。

任务行展示顺序建议：

```text
任务名 / 状态 / 风险
负责人 / 执行人 / 开始日期 / 截止日期 / 延期天数
操作：详情、编辑、补进展、补资料、子任务
```

## 12. 模板管理规范

模板管理必须按“大类 → 具体模板项”组织，不要把所有模板平铺在一个长列表里。

推荐结构：

```text
左侧：模板大类
  - 通用
  - 注册申报
  - 质量/GMP
  - 信息化项目

右侧：当前大类下的具体模板项
  - 模板名称
  - 模板描述
  - 阶段数
  - 任务数
  - 编辑 / 删除
```

规则：

- 左侧大类列表用于导航和过滤。
- 右侧只显示当前大类下的模板。
- 空大类要给出明确提示：“这个大类下还没有模板，可以点击新建模板。”
- 模板阶段和子任务支持拖动排序。
- 新系统不要自动生成不需要的预置模板；正式环境模板以迁移数据或人工维护为准。

## 13. 表单与弹窗规范

表单弹窗：

- 弹窗圆角：`20px`
- 标题字号：`20px` 左右，字重 `800`
- label 左侧对齐，宽度保持统一
- 必填字段用红色星号
- 底部按钮右对齐，顺序为：取消 / 主操作

输入控件：

- 默认边框：`#e4e7e5`
- focus：品牌色边框 + 浅品牌色外发光
- placeholder 使用浅灰，不要和正文一样重

```css
.el-input__wrapper.is-focus,
.el-select__wrapper.is-focused,
.el-textarea__inner:focus {
  box-shadow:
    0 0 0 1px #288174 inset,
    0 0 0 3px rgba(40, 129, 116, 0.16);
}
```

表单内容原则：

- 必填字段必须清晰。
- 低频字段不要放进主流程。
- 新建项目时“项目类别”为必填。
- 新建任务时不要展示交付物、优先级；这些不属于用户创建任务时必须思考的核心信息。

## 14. 进展与资料

任务详情使用“任务概况 / 进展与资料 / 操作日志”。进展日期、正文和资料同表单提交，资料名称自动获取；不再要求用户先建进展再填写资料名称。

- 电脑双栏：左侧表单在弹窗滚动时保持可见；表单高于可用区域时内部滚动，右侧长记录可继续浏览。
- 窄屏：上下排列，点击编辑定位表单；避免两栏挤压及提交按钮不可达。
- 正文输入随内容增长，约 6–16 行；不把长进展压在三行小框里。
- 上传、链接、飞书文件及“关联已有文件”在同一资料区域；共享引用不重复计数，解除关联须区别于删除原资料。
- 无资料时显示填写原因入口；已完成任务可补充，但归档/结项冻结时只读。
- 工作日期、原提交时间分别标注。合理补填使用独立状态，不把记录迟录直接渲染成工作延期。

新结项已经接入四部分绿色报告并附审核记录，历史报告按快照版本渲染，见 [报告模板说明](21-项目结项推送人力资源部（奖惩报备）方案.md)。折叠标题须有三角和展开/收起文字，整行可点；章节标题不能伪装成折叠按钮。

## 15. 文字、省略与 hover 规范

文字层级：

| 场景 | 字号 | 字重 |
| --- | --- | --- |
| 页面标题 | `20px ~ 24px` | `800 ~ 900` |
| 分组标题 | `18px ~ 22px` | `800 ~ 900` |
| 卡片标题 | `16px ~ 18px` | `700 ~ 900` |
| 正文 | `14px ~ 15px` | `400 ~ 600` |
| 元信息 | `12px ~ 13px` | `500 ~ 700` |
| 标签 | `11px ~ 12px` | `700 ~ 900` |

规则：

- 项目名、任务名、风险任务名必须加粗。
- 元信息用次级灰，不要和标题抢层级。
- 所有被省略号截断的文本都必须加 `title`，鼠标悬浮显示完整内容。
- 不只项目总览，任务列表、模板管理、用户管理、操作日志等类似位置都要统一处理。

## 16. 动效与交互

动效要克制：

- hover 上浮：`translateY(-1px)`
- hover 阴影略增强，不使用强烈发光
- 折叠展开可用轻微淡入或高度过渡
- 进度条不建议做明显流光，避免抢业务信息

基础过渡：

```css
--transition-fast: 120ms ease;
--transition-base: 180ms ease;
```

## 17. Do / Don’t

Do：

- 使用 `theme.css` 的统一变量。
- 用低饱和主题青建立品牌识别。
- 把延期、临期、待处理事项放到最容易看到的位置。
- 用缩进、连接线、左边框、字号一起表达层级。
- 长文本省略时加 hover 完整展示。
- 减少重复统计，让用户一眼看到重点。

Don’t：

- 不要每个页面自己发明一套颜色。
- 不要使用大面积高饱和蓝、绿、红、橙。
- 不要只靠颜色表达状态。
- 不要让部门、项目、父任务、子任务看起来像同一级。
- 不要把低频字段塞到主流程里。
- 不要为了“信息完整”把同一组数据在同一区域重复展示多遍。

## 20. 审批、日报与当前实现边界

- 审批使用“待我审批／我已审批／我发起的／与我相关”，历史按项目折叠，详情返回时保留原列表分类；任务历史不显示当前轮次的操作按钮。
- CountPill 与 MenuCountBadge 分别承载数量和导航提醒；工作日报提醒依赖服务端未读状态，不把访问菜单或本地缓存当作已经阅读全部日报。
- 进行中色为 --color-doing:#1e6fd9、背景 #e0f0ff；状态须同时提供文字，不能只靠颜色。
- theme.css 默认侧栏 224px、头部 56px；768px 为路由切换的重要边界，组件还有自己的断点。不要把桌面表格强行缩成手机页面。
- 本文“推荐”或示例 CSS 是设计约定，现有页面有局部样式；数值冲突以 theme.css 和具体组件实际声明为准。
- 公开版本使用中性 SVG 标识，业务版本可配置自己的授权品牌素材；不在可公开文档中嵌入组织 Logo 或真实人员截图。
